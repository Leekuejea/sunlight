# Sunlight

논문 PDF를 **레이아웃 그대로** 번역해 원문과 나란히 읽는 데스크톱 앱입니다 (macOS, Windows).
그림, 표, 수식 위치는 그대로 두고 문장만 번역문으로 바꿔 끼웁니다. 번역 방향은 영어 → 한국어, 한국어 → 영어입니다.

## 다운로드

[최신 릴리스](https://github.com/Leekuejea/sunlight/releases/latest)에서 내 컴퓨터에 맞는 파일을 받습니다.

| 컴퓨터 | 파일 |
|---|---|
| Mac (Apple Silicon: M1 이후) | `Sunlight_<버전>_aarch64.dmg` |
| Windows 10/11 | `Sunlight_<버전>_x64-setup.exe` |

macOS 13.4 이상, Apple Silicon Mac(M1 이후)이 필요합니다. 내 Mac 종류는  메뉴 > **이 Mac에 관하여**의 “칩” 항목에서 확인합니다. Intel Mac용은 제공하지 않습니다(내장한 ONNX Runtime 빌드가 Intel Mac을 지원하지 않음).

### 설치

**macOS**
1. `.dmg`를 열고 **Sunlight**를 **응용 프로그램** 폴더로 끌어다 놓습니다.
2. 처음 열 때 “‘Sunlight’을(를) 열지 않음” 또는 “확인되지 않은 개발자” 경고가 나오면 **완료**를 누른 뒤, **시스템 설정 > 개인정보 보호 및 보안** 맨 아래의 **그래도 열기**를 누르고 다시 엽니다. 이 앱은 Apple 개발자 인증서로 서명·공증하지 않았기 때문입니다. 이 단계를 건너뛰면 앱이 실행되지 않습니다.
3. “손상되었기 때문에 열 수 없습니다”라고 나오거나 2번에서 **그래도 열기**가 보이지 않으면, 터미널에서 다음을 한 번 실행한 뒤 다시 엽니다.
   ```sh
   xattr -cr /Applications/Sunlight.app
   ```

**Windows**
1. `-setup.exe`를 실행합니다. 관리자 권한 없이 현재 사용자에게 설치됩니다.
2. “Windows의 PC 보호” 창이 나오면 **추가 정보 > 실행**을 누릅니다. 코드 서명 인증서가 없는 앱이라 SmartScreen이 경고합니다.
3. 브라우저(Edge, Chrome)가 “일반적으로 다운로드되지 않는 파일”이라며 막으면 다운로드 목록에서 **…** > **유지**를 누릅니다.
4. v1.1.0 이하에서 `.msi`로 설치했다면 **설정 > 앱**에서 그 Sunlight를 먼저 제거합니다. 이제는 `-setup.exe` 하나만 배포하며, 두 가지로 모두 설치하면 Sunlight가 두 벌 생깁니다.

### 업데이트

앱이 스스로 업데이트합니다. 앱을 켜면 새 버전을 뒤에서 내려받아 두고, **앱을 닫을 때 설치**합니다. 번역이나 분석 중에 끊기지 않고, 다음에 켜면 새 버전입니다. 받아두면 “새 버전 x.y.z를 받아뒀어요” 알림이 뜨며, **지금 다시 시작**을 누르면 바로 적용합니다. **설정 > 일반 > 버전 > 업데이트 확인**으로 직접 확인할 수도 있습니다. (v1.2.0은 알림의 **업데이트**를 눌러야 설치됩니다.)
- 앱 안에서 받은 업데이트는 macOS의 “열지 않음” 경고가 다시 나오지 않습니다. 브라우저로 받은 파일에만 붙는 다운로드 표시가 없기 때문입니다.
- 업데이트 파일은 서명을 확인한 뒤에만 설치합니다.

v1.1.1 이하에서는 v1.2.0을 한 번만 직접 설치합니다. 새 버전의 설치 파일로 그대로 덮어 설치하면 되고, 앱을 켠 채로 설치해도 됩니다.
- **macOS**: `.dmg`의 Sunlight를 응용 프로그램 폴더에 끌어다 놓고 **대치**를 고릅니다. 위 2·3번 경고가 다시 나올 수 있습니다.
- **Windows**: 설치 프로그램이 실행 중인 Sunlight를 닫겠냐고 물으면 **확인**을 누릅니다. 앱 안 업데이트는 설치 창이 잠깐 보였다가 자동으로 끝납니다.
- 옛 버전이 켜져 있는 상태에서 새 버전을 열면, 옛 버전이 스스로 닫히고 새 버전이 열립니다(v1.1.1부터).
- 지금 실행 중인 버전은 **설정 > 일반 > 버전**에서 확인합니다.

## 처음 설정: 번역 엔진 고르기

앱 오른쪽 위 **설정 > 번역 엔진**에서 둘 중 하나를 고릅니다.

**A. 로컬 LLM (무료, 인터넷 없이, 논문이 컴퓨터 밖으로 나가지 않음)**
1. [Ollama](https://ollama.com/download)를 설치하고 실행합니다.
2. Sunlight **설정 > 번역 엔진 > 로컬 LLM**에서 모델 칩을 누르면 앱 안에서 내려받습니다.
   - `gemma4:e4b` (9.5GB): 기본 추천, 쪽당 약 45초 (16GB M2 Pro 기준)
   - `gemma4:12b` (7.7GB): 정확도 우선, 쪽당 약 90초
3. 메모리 16GB 이상을 권장합니다.

**B. API (빠름, 사용량만큼 요금)**
1. 쓰려는 서비스에서 API 키를 발급받습니다. [OpenAI](https://platform.openai.com/api-keys), [Anthropic Claude](https://console.anthropic.com/settings/keys), [Google Gemini](https://aistudio.google.com/apikey), [LG EXAONE](https://docs.exaone.ai/ko/docs/authentication)
2. **설정 > API 키**에 붙여 넣고 저장합니다. 저장하면서 키가 맞는지 바로 확인합니다.
3. **설정 > 번역 엔진**에서 그 서비스와 모델을 고릅니다. **연결 테스트**로 동작을 확인할 수 있습니다.

API 키는 macOS 키체인 또는 Windows 자격 증명 관리자에 저장되고, 화면에는 끝 4자리만 보입니다.
API를 고르면 번역할 문장이 그 서비스로 전송됩니다. 로컬 LLM은 모든 처리를 내 컴퓨터에서 합니다.

## 사용 방법

1. **논문 추가**: 첫 화면에서 **PDF 업로드**를 누르거나 PDF 파일을 창에 끌어다 놓습니다. 한 개를 올리면 바로 열립니다.
2. **번역 켜기**: 위쪽의 **레이아웃 유지 번역** 버튼을 누릅니다. 지금 보는 쪽부터 문서 전체를 번역하고, 위쪽에 “번역 중 n/전체쪽”이 보입니다. 다시 누르면(**원본으로 돌아가기**) 원문만 봅니다.
3. **보기 방식**: 번역 화면 위의 **나란히 보기**(원문 | 번역)와 **번역만 보기** 중에서 고릅니다. 창이 좁으면 번역만 보여 줍니다.
4. **문장 대응**: 번역문이나 원문 문장 위에 마우스를 올리면 반대편의 같은 문장이 강조됩니다.
5. **메모**: 원문이나 번역문의 문장을 클릭하면 오른쪽에 메모 창이 열립니다.
   - 메모를 쓰면 문장에 형광펜이 칠해지고, 노랑과 주황 중에서 색을 고를 수 있습니다.
   - 메모에 적은 웹 주소(`https://…`, `www.…`)는 누르면 기본 브라우저에서 열립니다.
   - 메모 카드의 인용문을 누르면 그 문장으로 이동합니다. ✕로 지우고, 지운 직후 **되돌리기**로 복구합니다.
   - 아무것도 쓰지 않은 메모는 저장되지 않습니다. 메모 하나는 2,000자까지입니다.
   - 메모는 자동 저장되고, 번역 캐시를 비우거나 엔진·언어를 바꿔도 남습니다. 논문을 라이브러리에서 삭제하면 함께 지워집니다.
6. **스크롤**: 한쪽을 스크롤하면 반대쪽이 같은 위치로 따라옵니다.
7. **확대·축소**
   - 트랙패드 핀치: 나란히 보기에서는 손가락을 올린 쪽 화면만 확대·축소됩니다.
   - 위쪽 −/+ 버튼, 배율 메뉴, ⌘+ / ⌘− / ⌘0 (Windows는 Ctrl): 두 화면을 같은 배율로 맞춥니다.
8. **번역 언어**: 위쪽 언어 메뉴에서 한국어/English를 바꿉니다.
9. **번역본 저장**: **번역 PDF 저장**을 누르면 번역이 끝난 PDF가 `문서/Sunlight/Translations` 폴더에 저장됩니다. 저장 후 알림의 **열기**로 바로 볼 수 있습니다.
10. **번역본 관리**: 첫 화면의 **번역본 보기**에서 저장한 PDF를 열거나 삭제하고, 폴더를 엽니다.
11. **번역 캐시**: 한 번 번역한 문장은 저장해 두었다가 다시 열 때 즉시 보여 줍니다. 번역을 처음부터 다시 받고 싶으면 **번역본 보기 > 번역 캐시 > 비우기**를 누릅니다.
12. **논문 삭제**: 첫 화면 카드의 **라이브러리에서 삭제**를 누릅니다. 이미 저장한 번역본 PDF는 지워지지 않습니다.
13. **화면 설정**: **설정 > 일반**에서 라이트/다크/시스템 모드, 눈이 편한 “보기 편한 모드”, 기본 번역 언어를 고릅니다.
14. **그래프**: 위쪽 **그래프** 탭에서 **주제 찾기**를 누르면, 지금 번역 엔진이 논문마다 앞부분을 한 번 읽고 주제를 찾습니다. 같은 주제를 다룬 논문끼리, 그리고 참고문헌에서 서로 인용한 논문끼리 이어져 묶음별 색으로 그려집니다.
    - 네모는 논문, 점은 주제입니다. 누르면 오른쪽에 요약·주제·인용 관계가 나오고, 논문을 두 번 누르거나 **논문 열기**를 누르면 바로 열립니다.
    - 오른쪽 위 검색으로 논문이나 주제를 찾고, 묶음 목록의 체크로 묶음을 숨깁니다.
    - 결과는 저장되어 다음부터 바로 그려집니다. 새로 추가한 논문만 **주제 찾기 · n편**으로 이어서 분석합니다. 더 좋은 모델로 바꿨다면 **다시 분석**을 누릅니다.
    - API 엔진은 논문마다 한 번 요청하므로 그만큼 사용량이 듭니다.

## 문제 해결

| 증상 | 해결 |
|---|---|
| 쪽마다 “번역 서버에 연결하지 못했어요” | 로컬 LLM이면 Ollama가 실행 중인지 확인합니다. API면 **설정 > 번역 엔진 > 연결 테스트**로 키와 모델을 확인합니다. |
| 일부 쪽만 번역 실패 | 그 쪽의 **다시 시도**를 누릅니다. 인터넷이 다시 연결되면 실패한 쪽을 자동으로 다시 번역합니다. |
| 연결 테스트가 “40초 안에 답이 없어요”로 끝남 | 로컬 LLM은 다른 쪽을 번역 중이거나 모델을 처음 불러오는 중입니다. 잠시 후 다시 누릅니다. API는 무료 요금제의 분당 요청 한도(429)에 걸렸을 수 있습니다. 1분쯤 뒤 다시 시도하거나 유료 요금제·다른 모델을 씁니다. |
| 엔진이나 모델을 바꿨는데 예전 번역이 보임 | 바꾸면 열린 논문을 새 모델로 자동으로 다시 번역합니다. 이미 그 모델로 번역한 문장은 캐시에서 바로 보여 줍니다. |
| 번역이 매우 느림 | 로컬 모델은 첫 번역 때 모델을 메모리에 올리느라 10초 정도 더 걸립니다. 더 빠르게 하려면 `gemma4:e4b` 또는 API를 씁니다. |
| 번역문이 이상하거나 오래된 결과가 보임 | **번역본 보기 > 번역 캐시 > 비우기** 후 다시 엽니다. |
| Mac에서 앱이 열리지 않음 | 위 [설치](#설치)의 macOS 2, 3번을 따릅니다. |
| 새 버전을 설치했는데 새 기능이 보이지 않음 | **설정 > 일반 > 버전**을 확인합니다. 옛 버전이면 앱을 완전히 종료(Mac: ⌘Q, Windows: 창 닫기)한 뒤 다시 엽니다. Mac에서는 경고 때문에 새 버전이 실행되지 않았을 수 있으니 설치 2·3번을 따릅니다. 응용 프로그램 폴더 밖(다운로드 폴더 등)에 옛 Sunlight 사본이 있으면 지웁니다. |

# 개발자 문서

themoonlight.io(3.7.5)의 레이아웃 유지 번역 동작을 분석해 다시 구현했습니다.

## 번역 엔진

번역 엔진은 **설정 > 번역 엔진**에서 고릅니다.

| 엔진 | 호출 방식 | 기본 모델 |
|---|---|---|
| 로컬 LLM (Ollama) | 네이티브 `/api/chat`, thinking 끔 | `gemma4:e4b` |
| EXAONE | `api.exaone.ai/v1` (OpenAI 호환 SSE) | `k-exaone_v2.5` |
| GPT | `api.openai.com/v1` chat completions | 키로 조회한 목록 중 `gpt-*-mini` 우선 |
| Claude | Messages API 직접 호출(공식 Rust SDK 없음) | `claude-opus-5-5` |
| Gemini | Gemini OpenAI 호환 엔드포인트 | 키로 조회한 목록 중 `gemini-*-flash` 우선 |

API 모델 목록은 하드코딩하지 않고, 저장한 키로 각 제공사의 목록 API를 호출해 채웁니다. 이 호출이 곧 키 확인입니다.
추론 강도(effort)는 기본값이 “낮음”이고, 번역에는 이 정도로 충분합니다.
Claude Opus 5.5와 Sonnet 5.5에는 거절 시 다른 모델로 재시도하는 `fallbacks: "default"`(`server-side-fallback-2026-07-01`)가 켜져 있습니다.

### 로컬 모델 선정 (16GB M2 Pro, CS-Pi 논문 2쪽 30문장 실측)

| 모델 | 시간 | 예산 초과 | 비고 |
|---|---|---|---|
| **gemma4:e4b** (기본) | 46.7초 | 0 | 문장이 자연스럽고 LaTeX 변환이 정확함 |
| gemma4:12b | 87.6초 | 0 | 용어 보존이 가장 좋음(정확도 우선 옵션) |
| qwen3.5:9b | 80.7초 | 2 | proxy를 “대용기”로 옮기는 등 용어 오역 |
| exaone3.5:7.8b | 66.4초 | – | 인명과 학회명을 음역함(사용자 요청으로 제외) |

## 구조

| 부분 | 기술 | 위치 |
|---|---|---|
| 앱 셸 | Tauri 2 (Mac은 WKWebView, Windows는 WebView2) | `src-tauri/` |
| 백엔드 | Rust: axum 로컬 서버, reqwest 스트리밍 | `src-tauri/src/server.rs`, `llm.rs`, `store.rs` |
| 번역 하네스 | Rust | `src-tauri/src/harness.rs` |
| 레이아웃 감지 | ONNX Runtime 내장(Mac은 Core ML 가속), DocLayout-YOLO | `src-tauri/src/detect.rs` |
| 화면 | React + PDF.js 4.5.136(legacy 빌드) | `src/` |

화면은 백엔드가 여는 `127.0.0.1:47613`에서만 불러오고, Tauri IPC 명령은 쓰지 않습니다(창 드래그 권한만 허용).
서버는 Host와 Origin 헤더를 검사해 다른 웹사이트의 호출을 403으로 막습니다.

## 실행과 빌드

```sh
brew install rustup && rustup default stable   # Rust 툴체인 (최초 1회)
npm install
npm run build        # dist/ 생성. Rust 크레이트가 dist/를 내장하므로 cargo 빌드·테스트 전에 한 번 필요
npm run dev          # tauri dev
npm test             # 프런트 parity 테스트 + Rust 단위 테스트 (첫 실행 때 arXiv에서 테스트용 논문 PDF를 받음)
npm run dist         # src-tauri/target/release/bundle/ 아래 .app, .dmg (Windows에서는 .msi, .exe)
```

- Windows 설치 파일은 Windows에서 빌드해야 합니다. `.github/workflows/release.yml`이 `v*` 태그를 푸시하면 Mac(Apple Silicon)과 Windows용을 함께 만들어 GitHub 릴리스에 올립니다.
- `main`에 푸시하면 `.github/workflows/ci.yml`이 빌드와 테스트를 돌립니다.
- 앱 안 업데이트(`src-tauri/src/update.rs`, `tauri-plugin-updater`)는 릴리스의 `latest.json`을 확인합니다. 앱을 켤 때 `POST /api/update/prefetch`가 패키지를 내려받아 서명까지 확인한 뒤 메모리에 두고, 앱이 끝날 때(`RunEvent::Exit`) 다시 시작 없이 설치합니다. 업데이트 패키지는 CI가 `TAURI_SIGNING_PRIVATE_KEY`(저장소 Secret)로 서명하고, 앱은 `tauri.conf.json`의 공개 키로 검증합니다. 이 개인 키를 잃으면 기존 설치본에 업데이트를 보낼 수 없으니 따로 백업해 둡니다. 로컬 시험은 `SUNLIGHT_UPDATE_URL`로 다른 `latest.json`을 가리키게 할 수 있습니다(https만 허용).
- Mac 빌드는 ad-hoc 서명입니다. Developer ID 서명과 공증을 하려면 저장소 시크릿에 `APPLE_*` 값을 넣고 `release.yml`의 env에 연결합니다(빈 값을 넘기면 빌드가 실패합니다).
- 최소 macOS는 13.4입니다(ONNX Runtime 요구 사항).
- 로컬 번역에는 [Ollama](https://ollama.com)가 설치되어 있어야 합니다.

API 키 저장과 확인, 엔진과 모델 선택, 로컬 모델 내려받기, 연결 테스트는 앱의 **설정** 창에서 합니다.
API 키는 OS 키체인(macOS 키체인, Windows 자격 증명 관리자)에 저장하고, 화면에는 끝 4자리만 보냅니다.

## 모바일 (iOS, Android)

같은 코드로 Tauri 2 모바일 타깃을 빌드합니다(브랜치 `mobile`). 데스크톱 앱과 다른 점은 세 가지입니다.

- 번역만 보기로 고정합니다(나란히 보기 없음).
- 번역 엔진은 API만 씁니다(로컬 LLM 없음).
- 앱 안 업데이트와 “폴더 열기”가 없습니다. 저장한 번역본은 공유 시트로 내보냅니다.

```sh

npm run build                                   # dist/ (Rust 크레이트가 내장)
npx tauri ios dev "iPhone 18 Pro"               # 시뮬레이터. 먼저 xcrun simctl boot 로 켜 둡니다
NDK_HOME=$ANDROID_HOME/ndk/<버전> npx tauri android dev   # 에뮬레이터 또는 연결된 기기
```

|---|---|

## 번역 하네스 (`src-tauri/src/harness.rs`)

- **시스템 프롬프트**는 연구 논문 번역이라는 점과, 번역문이 원문 문장이 있던 PDF 상자에 다시 조판된다는 점을 알립니다. 길이를 정확도만큼 중요한 제약으로 둡니다.
- **문장별 글자 수 예산**: 한국어는 원문 길이의 0.7배, 영어는 1.6배입니다. Moonlight가 실제로 레이아웃에 맞춘 번역문의 길이 비율(중앙값 0.61, 90% 구간 0.74)에서 정했습니다. 예산은 요청에 `Character limits: 0:70, 1:85, …`로 함께 보냅니다.
- **사후 검사**: 예산의 1.25배를 넘은 문장은 압축을 한 번 다시 요청합니다. 예산의 0.35배보다 짧으면 내용이 빠진 것으로 보고 원문으로 되돌립니다(예: 저자 블록이 이름만 남은 경우). LaTeX는 렌더된 길이로 셉니다.
- **출력 형식**은 `<|i|>번역` 마커입니다(Moonlight 서버 응답 형식). 다음 마커가 도착하는 즉시 앞 문장을 확정하고, 빠진 문장은 원문으로 둡니다. 모델이 `<|4>`, `<|4` 같이 마커를 잘못 써도 문장을 나누고, 남은 마커 조각은 지웁니다. 뷰어도 마커가 반복되거나 순서가 어긋나면 그 마커만 무시합니다(Moonlight는 쪽 전체를 버림).
- **스트림 유지**: 첫 문장을 10초 기다린 뒤 응답을 시작하고, 15초마다 빈 줄을 보냅니다. WebKit은 60초 동안 데이터가 없으면 요청을 끊기 때문입니다. 응답이 시작된 뒤의 엔진 오류는 `<|error|>상태|메시지` 줄로 알립니다.
- **취소**: 뷰어가 요청을 끊으면(문서 닫기, 언어·엔진 변경) 서버는 즉시 엔진 요청을 끊고 로컬 모델 차례를 넘깁니다.
- **그 밖의 규칙**: 수식은 `$LaTeX$`로 씁니다. 인용, 그림·표·절 번호, 고유명사, 저자와 학회 줄은 그대로 둡니다. 한국어 번역 예시 한 쌍을 함께 보냅니다.
- **원문 유지**: 이메일이나 URL이 든 짧은 문장(저자·소속 블록)은 모델에 보내지 않습니다.
- **재시도**: 429는 `retry-after` 헤더나 Gemini 응답 본문의 `retryDelay`를 따르고, 없으면 지수 백오프로 최대 5회 재시도합니다.
- **시간 제한**: 연결 테스트는 40초, API 키 확인(모델 목록)은 20초 안에 답합니다.
- **로컬 모델**: 한 쪽을 12문장 단위로 나눠 보내 앞부분이 먼저 나오게 하고, 요청은 한 번에 하나씩 처리합니다.
- **캐시**: 문장 단위로 한 줄씩 덧붙여 저장합니다. 모델이 빠뜨린 문장은 캐시하지 않습니다.

## 읽기 기능

- **진행도**: 레이아웃 유지 번역을 켜면 문서 전체를 백그라운드에서 번역하고, 상단에 “번역 중 n/전체쪽”과 진행 막대를 보여 줍니다. 지금 보는 쪽부터 뒤로 처리하고, 앞쪽은 마지막에 처리합니다.
- **확대·축소**: −/+ 버튼, 배율 메뉴, 트랙패드 핀치(포인터 위치 기준, Chromium의 ctrl+휠과 WebKit의 제스처 이벤트 모두 처리), ⌘+ / ⌘− / ⌘0을 지원합니다. 나란히 보기에서 핀치는 포인터 아래 화면만 확대하고, 버튼·메뉴·단축키는 두 화면을 같은 배율로 맞춥니다. 스크롤은 쪽 안의 위치 비율로 맞추므로 배율이 달라도 따라갑니다.
- **스크롤 동기화**: 휠 입력은 두 화면을 같은 프레임에 함께 움직입니다. 스크롤바 드래그와 키보드는 스크롤 이벤트로 맞춥니다.
- **확인 창**: Tauri 웹뷰에서 `window.confirm()`은 창을 띄우지 않고 `false`를 돌려주므로, 삭제와 비우기 확인은 앱이 직접 그립니다.
- **레이아웃 감지 입력**: 화면 캔버스 대신 긴 변 2048px로 따로 렌더한 쪽 이미지를 보냅니다. 확대 배율과 상관없이 같은 결과가 나오고, 확대 중 캔버스가 비워져도 감지가 실패하지 않습니다.
- **설정 창**은 일반(라이트·다크·시스템, 보기 편한 모드, 번역 언어), 번역 엔진, API 키 탭으로 나뉩니다. 다크 모드와 보기 편한 모드는 PDF 캔버스와 번역 블록에 같은 필터를 적용해 덮개 색이 어긋나지 않게 합니다.

## 메모 (`src/layout/memos.js`)

한컴오피스 한글(12.30.0, macOS)의 메모 기능을 분석해 구조를 따랐습니다. 근거는 앱에 든 `memo_preset.hwp`의 레코드, 리소스 문자열, `HwpApp.dylib`의 클래스 이름입니다.

| 한글에서 관찰한 것 | 근거 | Sunlight |
|---|---|---|
| 메모는 본문에 낀 **필드**다. 시작·끝 표식(0x03, 0x04)이 본문 범위를 감싸고, 필드에는 `MEMO/65535/번호/날짜/시간/작성자/…` 명령 문자열과 메모 id만 있다 | `memo_preset.hwp` 본문 레코드, `CHwpFieldMemo` | 앵커 = 쪽 + 원문 문장 번호들 + 그 문장의 글. 번호가 달라져도 글로 다시 찾는다 |
| 메모 **내용은 본문과 따로** 구역 끝의 메모 목록(`MEMO_LIST`, id로 연결)에 문단으로 저장된다 | 같은 파일, `CHwpMemoTextList`, `CHwpMemoMapper` | 문서마다 `memos/<id>.json`. 번역 캐시·PDF와 분리 |
| **메모 모양**은 문서 정보에 22바이트로 저장: 너비(14173 HWPUNIT ≈ 50mm), 선 종류·굵기·색, 배경색, **선택 색**, 종류 | `MEMO_SHAPE` 레코드 10개, “[메모 색-배경 색]”, “[메모 색-선택 색]” 문자열 | 색 2종(노랑·주황)과 각각의 선택(활성) 색. 메모 창 너비 300px 고정 |
| 머리말은 `[메모:%d] 작성자, 날짜`. 다음/이전 이동, 메모 내용 보기 창, 메모 안내선, 지우기가 있다 | `IDS_MEMO_HEAD`, `HWPAID_MEMO_TO_NEXT` 등 | 카드 머리말 “메모 n · 쪽 · 날짜”, 카드 클릭으로 이동, ✕ 지우기 |

코드 디컴파일(REA/Hopper)은 13MB 바이너리 초기 분석이 시간 초과되어 쓰지 못했고, 위 내용은 파일과 리소스에서 확인한 것입니다.

설계 결정:
- **저장**: 문서당 JSON 한 파일을 통째로 원자적 쓰기(임시 파일 후 이름 바꾸기). 입력 0.5초 뒤 자동 저장, 실패하면 5초마다 재시도, 창을 닫을 때 한 번 더 저장. 저장된 메모를 읽지 못하면 덮어쓰지 않도록 저장과 새 메모를 막는다. 리더가 다시 만들어질 때(언어·엔진 변경)는 앞선 저장이 끝난 뒤 읽는다.
- **빈 메모**: 포커스를 잃을 때 내용이 없으면 버린다. 저장된 메모를 비우면 삭제된다.
- **긴 메모**: 2,000자 제한(1,600자부터 글자 수 표시). 입력창은 화면 높이의 40%까지 늘어난 뒤 안에서 스크롤, 표시는 6줄로 접고 “더 보기”.
- **확대·축소**: 메모 창은 PDF 뷰어 밖에 있어 배율과 무관하고, 창 위에서의 핀치는 막는다. 하이라이트는 `--scale-factor`로 위치를 계산하고, PDF.js가 쪽을 다시 그릴 때마다 다시 칠한다.
- **앵커를 못 찾을 때**: 카드에 안내를 띄우고 메모 내용은 보관한다.
- **링크**: `http(s)://`와 `www.` 주소만 링크로 만들고, 앱의 외부 링크 처리기가 기본 브라우저로 연다.
- 메모는 레이아웃 유지 번역을 켠 상태에서 동작하고, 번역 PDF 저장에는 포함되지 않는다.

## 그래프 (`src/graph/`, `src-tauri/src/graph.rs`)

[graphify](https://github.com/Graphify-Labs/graphify)(0.9.109, Apache-2.0)가 `graph.html`을 만드는 과정을 따랐습니다. graphify는 파이썬 소스로 배포되므로 디컴파일 없이 설치된 소스(`exporters/html.py`, `cluster.py`, `build.py`, `analyze.py`)를 읽고, 같은 그래프에 대해 결과를 비교했습니다.

| graphify | Sunlight |
|---|---|
| 감지: 파일을 코드·문서·논문·이미지로 나눔 | 라이브러리의 PDF |
| 의미 추출: LLM이 문서마다 개념 노드와 관계(EXTRACTED/INFERRED/AMBIGUOUS)를 JSON으로 냄. 파일 내용 해시 + 프롬프트로 캐시 | 지금 번역 엔진이 논문 앞 3쪽(최대 6,000자)을 읽고 `{title, topics, summary}`를 냄. 문서 id(내용 해시) + 프롬프트 버전으로 캐시(`graph/<id>.json`) |
| 빌드: networkx 무방향 그래프, id 정규화로 중복 노드 합침 | 논문 노드 + 주제 노드. 주제는 소문자·구두점 제거·복수형 정리로 합침(`topicKey`). 관계는 `covers`(논문→주제), `cites`(참고문헌에 다른 논문 제목이 그대로 있으면, 4단어 이상만) |
| 군집: Leiden(graspologic), 없으면 networkx Louvain(seed 42, threshold 1e-4, max_level 10). 고립 노드는 단독 묶음, 전체의 25%(최소 10)를 넘는 묶음은 다시 나누고, 50개 이상이면서 응집도 0.05 미만인 묶음도 다시 나눔. 크기 내림차순으로 번호 | networkx Louvain을 JS로 옮김(`louvain`, 같은 규칙). 같은 그래프 3개(karate, planted partition 120노드, 이 저장소 672노드)에서 networkx와 묶음 수가 같고 modularity가 같거나 약간 높음 |
| 이름: 에이전트/LLM이 붙이거나, 없으면 차수가 가장 큰 허브 노드 이름 | 허브 이름. 단, 주제 노드 중에서 고르고 차수가 같으면 모델이 먼저 적은 주제(넓은 분야) |
| 그리기: vis-network 9.1.6, forceAtlas2Based(중력 −60, 중심 0.005, 스프링 120·0.08, 감쇠 0.4, 겹침 회피 0.8), 200회 안정화 후 물리 끔, 황금각 나선 초기 위치, 크기 10+30×차수/최대차수, 최대 차수의 15% 이상만 이름 표시, 색 10개 팔레트 | 같은 버전·같은 옵션(npm 번들, 그래프 탭에서만 불러옴). 논문은 네모로 항상 이름 표시, 인용선은 파란 화살표 |
| 사이드바: 검색, 노드 정보·이웃, 묶음 체크박스, 통계(innerHTML) | 같은 구성을 React로. 라벨은 텍스트로만 넣음 |

논문을 하나씩 따로 읽으면 같은 분야가 매번 다르게 적혀(“robotics”, “robot learning”, “robot control”) 논문이 서로 이어지지 않습니다. 실측에서 4편이 모두 따로 떨어졌습니다. 그래서 이미 쓰인 주제 목록(많이 쓰인 순, 최대 200개)을 요청에 함께 보내고 그 표현을 다시 쓰게 합니다. 이후 같은 4편이 “robot learning”, “sim-to-real transfer” 등으로 이어졌습니다.

- **응답 유지**: 분석 요청은 15초마다 빈 줄을 보내 WebKit의 60초 제한을 넘기고, 마지막 줄에 `{ok, paper}` 또는 `{ok:false, error}`를 보냅니다. 페이지가 요청을 끊으면(중지, 화면 이동) 엔진 요청도 끊깁니다.
- **실패**: 논문마다 오류를 모아 알리고, 두 편 연속 실패하면 엔진 문제로 보고 멈춥니다(키 없음, Ollama 꺼짐).
- **백그라운드**: macOS WebKit은 가려지거나 최소화된 창의 페이지를 멈춥니다. 창 옵션 `backgroundThrottling: disabled`로 다른 앱을 보는 동안에도 분석과 번역이 계속됩니다(macOS 14 이상).
- graphify의 하이퍼엣지(3개 이상 노드를 묶는 음영 영역)와 군집 이름용 LLM 호출, 퍼지 중복 제거는 넣지 않았습니다.
