# Sunlight

논문 PDF를 **레이아웃 그대로** 번역해 원문과 나란히 읽는 데스크톱 앱입니다 (macOS, Windows).
그림, 표, 수식 위치는 그대로 두고 문장만 번역문으로 바꿔 끼웁니다. 번역 방향은 영어 → 한국어, 한국어 → 영어입니다.

## 다운로드

[최신 릴리스](https://github.com/Leekuejea/sunlight/releases/latest)에서 내 컴퓨터에 맞는 파일을 받습니다.

| 컴퓨터 | 파일 |
|---|---|
| Mac (Apple Silicon: M1 이후) | `Sunlight_<버전>_aarch64.dmg` |
| Mac (Intel) | `Sunlight_<버전>_x64.dmg` |
| Windows 10/11 | `Sunlight_<버전>_x64-setup.exe` |

macOS 13.4 이상이 필요합니다. 내 Mac 종류는  메뉴 > **이 Mac에 관하여**의 “칩” 항목에서 확인합니다.

### 설치

**macOS**
1. `.dmg`를 열고 **Sunlight**를 **응용 프로그램** 폴더로 끌어다 놓습니다.
2. 처음 열 때 “확인되지 않은 개발자” 경고가 나오면 **시스템 설정 > 개인정보 보호 및 보안** 맨 아래의 **그래도 열기**를 누릅니다. 이 앱은 Apple 개발자 인증서로 서명하지 않았기 때문입니다.
3. “손상되었기 때문에 열 수 없습니다”라고 나오면 터미널에서 다음을 한 번 실행한 뒤 다시 엽니다.
   ```sh
   xattr -cr /Applications/Sunlight.app
   ```

**Windows**
1. `-setup.exe`를 실행합니다. 관리자 권한 없이 현재 사용자에게 설치됩니다.
2. “Windows의 PC 보호” 창이 나오면 **추가 정보 > 실행**을 누릅니다.

## 처음 설정: 번역 엔진 고르기

앱 오른쪽 위 **설정 > 번역 엔진**에서 둘 중 하나를 고릅니다.

**A. 로컬 LLM (무료, 인터넷 없이, 논문이 컴퓨터 밖으로 나가지 않음)**
1. [Ollama](https://ollama.com/download)를 설치하고 실행합니다.
2. Sunlight **설정 > 번역 엔진 > 로컬 LLM**에서 모델 칩을 누르면 앱 안에서 내려받습니다.
   - `gemma4:e4b` (9.5GB): 기본 추천, 쪽당 약 45초 (16GB M2 Pro 기준)
   - `gemma4:12b` (7.7GB): 정확도 우선, 쪽당 약 90초
3. 메모리 16GB 이상을 권장합니다.

**B. API (빠름, 사용량만큼 요금)**
1. 쓰려는 서비스에서 API 키를 발급받습니다. [OpenAI](https://platform.openai.com/api-keys), [Anthropic Claude](https://console.anthropic.com/settings/keys), [Google Gemini](https://aistudio.google.com/apikey), [LG EXAONE](https://docs.exaone.ai/ko/docs/authentication)
2. **설정 > API 키**에 붙여 넣고 저장합니다. 저장하면서 키가 맞는지 바로 확인합니다.
3. **설정 > 번역 엔진**에서 그 서비스와 모델을 고릅니다. **연결 테스트**로 동작을 확인할 수 있습니다.

API 키는 macOS 키체인 또는 Windows 자격 증명 관리자에 저장되고, 화면에는 끝 4자리만 보입니다.
API를 고르면 번역할 문장이 그 서비스로 전송됩니다. 로컬 LLM은 모든 처리를 내 컴퓨터에서 합니다.

## 사용 방법

1. **논문 추가**: 첫 화면에서 **PDF 업로드**를 누르거나 PDF 파일을 창에 끌어다 놓습니다. 한 개를 올리면 바로 열립니다.
2. **번역 켜기**: 위쪽의 **레이아웃 유지 번역** 버튼을 누릅니다. 지금 보는 쪽부터 문서 전체를 번역하고, 위쪽에 “번역 중 n/전체쪽”이 보입니다. 다시 누르면(**원본으로 돌아가기**) 원문만 봅니다.
3. **보기 방식**: 번역 화면 위의 **나란히 보기**(원문 | 번역)와 **번역만 보기** 중에서 고릅니다. 창이 좁으면 번역만 보여 줍니다.
4. **문장 대응**: 번역문이나 원문 문장 위에 마우스를 올리면 반대편의 같은 문장이 강조됩니다.
5. **스크롤**: 한쪽을 스크롤하면 반대쪽이 같은 위치로 따라옵니다.
6. **확대·축소**
   - 트랙패드 핀치: 나란히 보기에서는 손가락을 올린 쪽 화면만 확대·축소됩니다.
   - 위쪽 −/+ 버튼, 배율 메뉴, ⌘+ / ⌘− / ⌘0 (Windows는 Ctrl): 두 화면을 같은 배율로 맞춥니다.
7. **번역 언어**: 위쪽 언어 메뉴에서 한국어/English를 바꿉니다.
8. **번역본 저장**: **번역 PDF 저장**을 누르면 번역이 끝난 PDF가 `문서/Sunlight/Translations` 폴더에 저장됩니다. 저장 후 알림의 **열기**로 바로 볼 수 있습니다.
9. **번역본 관리**: 첫 화면의 **번역본 보기**에서 저장한 PDF를 열거나 삭제하고, 폴더를 엽니다.
10. **번역 캐시**: 한 번 번역한 문장은 저장해 두었다가 다시 열 때 즉시 보여 줍니다. 번역을 처음부터 다시 받고 싶으면 **번역본 보기 > 번역 캐시 > 비우기**를 누릅니다.
11. **논문 삭제**: 첫 화면 카드의 **라이브러리에서 삭제**를 누릅니다. 이미 저장한 번역본 PDF는 지워지지 않습니다.
12. **화면 설정**: **설정 > 일반**에서 라이트/다크/시스템 모드, 눈이 편한 “보기 편한 모드”, 기본 번역 언어를 고릅니다.

## 문제 해결

| 증상 | 해결 |
|---|---|
| 쪽마다 “번역 서버에 연결하지 못했어요” | 로컬 LLM이면 Ollama가 실행 중인지 확인합니다. API면 **설정 > 번역 엔진 > 연결 테스트**로 키와 모델을 확인합니다. |
| 일부 쪽만 번역 실패 | 그 쪽의 **다시 시도**를 누릅니다. 인터넷이 다시 연결되면 실패한 쪽을 자동으로 다시 번역합니다. |
| 번역이 매우 느림 | 로컬 모델은 첫 번역 때 모델을 메모리에 올리느라 10초 정도 더 걸립니다. 더 빠르게 하려면 `gemma4:e4b` 또는 API를 씁니다. |
| 번역문이 이상하거나 오래된 결과가 보임 | **번역본 보기 > 번역 캐시 > 비우기** 후 다시 엽니다. |
| Mac에서 앱이 열리지 않음 | 위 [설치](#설치)의 macOS 2, 3번을 따릅니다. |

# 개발자 문서

themoonlight.io(3.7.5)의 레이아웃 유지 번역 동작을 분석해 다시 구현했습니다.

## 번역 엔진

번역 엔진은 **설정 > 번역 엔진**에서 고릅니다.

| 엔진 | 호출 방식 | 기본 모델 |
|---|---|---|
| 로컬 LLM (Ollama) | 네이티브 `/api/chat`, thinking 끔 | `gemma4:e4b` |
| EXAONE | `api.exaone.ai/v1` (OpenAI 호환 SSE) | `k-exaone_v2.5` |
| GPT | `api.openai.com/v1` chat completions | 키로 조회한 목록 중 `gpt-*-mini` 우선 |
| Claude | Messages API 직접 호출(공식 Rust SDK 없음) | `claude-opus-5-5` |
| Gemini | Gemini OpenAI 호환 엔드포인트 | 키로 조회한 목록 중 `gemini-*-flash` 우선 |

API 모델 목록은 하드코딩하지 않고, 저장한 키로 각 제공사의 목록 API를 호출해 채웁니다. 이 호출이 곧 키 확인입니다.
추론 강도(effort)는 기본값이 “낮음”이고, 번역에는 이 정도로 충분합니다.
Claude Opus 5.5와 Sonnet 5.5에는 거절 시 다른 모델로 재시도하는 `fallbacks: "default"`(`server-side-fallback-2026-07-01`)가 켜져 있습니다.

### 로컬 모델 선정 (16GB M2 Pro, CS-Pi 논문 2쪽 30문장 실측)

| 모델 | 시간 | 예산 초과 | 비고 |
|---|---|---|---|
| **gemma4:e4b** (기본) | 46.7초 | 0 | 문장이 자연스럽고 LaTeX 변환이 정확함 |
| gemma4:12b | 87.6초 | 0 | 용어 보존이 가장 좋음(정확도 우선 옵션) |
| qwen3.5:9b | 80.7초 | 2 | proxy를 “대용기”로 옮기는 등 용어 오역 |
| exaone3.5:7.8b | 66.4초 | – | 인명과 학회명을 음역함(사용자 요청으로 제외) |

## 구조

| 부분 | 기술 | 위치 |
|---|---|---|
| 앱 셸 | Tauri 2 (Mac은 WKWebView, Windows는 WebView2) | `src-tauri/` |
| 백엔드 | Rust: axum 로컬 서버, reqwest 스트리밍 | `src-tauri/src/server.rs`, `llm.rs`, `store.rs` |
| 번역 하네스 | Rust | `src-tauri/src/harness.rs` |
| 레이아웃 감지 | ONNX Runtime 내장(Mac은 Core ML 가속), DocLayout-YOLO | `src-tauri/src/detect.rs` |
| 화면 | React + PDF.js 4.5.136(legacy 빌드) | `src/` |

화면은 백엔드가 여는 `127.0.0.1:47613`에서만 불러오고, Tauri IPC 명령은 쓰지 않습니다(창 드래그 권한만 허용).
서버는 Host와 Origin 헤더를 검사해 다른 웹사이트의 호출을 403으로 막습니다.

## 실행과 빌드

```sh
brew install rustup && rustup default stable   # Rust 툴체인 (최초 1회)
npm install
npm run build        # dist/ 생성. Rust 크레이트가 dist/를 내장하므로 cargo 빌드·테스트 전에 한 번 필요
npm run dev          # tauri dev
npm test             # 프런트 parity 테스트 + Rust 단위 테스트 (첫 실행 때 arXiv에서 테스트용 논문 PDF를 받음)
npm run dist         # src-tauri/target/release/bundle/ 아래 .app, .dmg (Windows에서는 .msi, .exe)
```

- Windows 설치 파일은 Windows에서 빌드해야 합니다. `.github/workflows/release.yml`이 `v*` 태그를 푸시하면 Mac(Apple Silicon, Intel)과 Windows용을 함께 만들어 GitHub 릴리스에 올립니다.
- `main`에 푸시하면 `.github/workflows/ci.yml`이 빌드와 테스트를 돌립니다.
- Mac 빌드는 ad-hoc 서명입니다. Developer ID 서명과 공증을 하려면 저장소 시크릿에 `APPLE_*` 값을 넣고 `release.yml`의 env에 연결합니다(빈 값을 넘기면 빌드가 실패합니다).
- 최소 macOS는 13.4입니다(ONNX Runtime 요구 사항).
- 로컬 번역에는 [Ollama](https://ollama.com)가 설치되어 있어야 합니다.

API 키 저장과 확인, 엔진과 모델 선택, 로컬 모델 내려받기, 연결 테스트는 앱의 **설정** 창에서 합니다.
API 키는 OS 키체인(macOS 키체인, Windows 자격 증명 관리자)에 저장하고, 화면에는 끝 4자리만 보냅니다.

### 실측 (16GB M2 Pro)

| 항목 | 값 |
|---|---|
| 레이아웃 감지 | 쪽당 0.11초 (Core ML). CPU만 쓰면 0.9초, 이전 Python 서버는 별도 프로세스 필요 |
| 로컬 번역 (gemma4:e4b) | 약 45토큰/초, 30문장 한 쪽에 약 30초 |
| 로컬 요청 2개 동시 실행 | 순차 실행과 총 시간 같음 → 한 번에 하나만 처리 |
| 모델 첫 로드 | 약 12초 → 번역을 켤 때 미리 로드 |
| 설치 파일 | .dmg 80MB (그중 감지 모델 75MB) |

## 저장 공간

| 항목 | 위치 | 관리 |
|---|---|---|
| 번역본 PDF | `~/Documents/Sunlight/Translations/` | 번역본 탭에서 열기, 개별 삭제, 모두 삭제, Finder에서 열기 |
| 원본 라이브러리 | `~/Library/Application Support/Sunlight/library/` (Windows: `%APPDATA%\Sunlight`) | 라이브러리 카드에서 삭제 |
| 번역 캐시, 감지 결과, 썸네일 | 같은 폴더의 `translations.jsonl`, `boxes/`, `thumbs/` | 번역본 탭의 “비우기” |

번역본 PDF 용량은 대부분 원본 PDF 크기에서 옵니다. 원본 위에 번역 블록을 PNG로 덧붙이는 원본 방식을 그대로 따르기 때문입니다(번역 오버레이는 쪽당 약 0.5~1MB).

## 번역 하네스 (`src-tauri/src/harness.rs`)

- **시스템 프롬프트**는 연구 논문 번역이라는 점과, 번역문이 원문 문장이 있던 PDF 상자에 다시 조판된다는 점을 알립니다. 길이를 정확도만큼 중요한 제약으로 둡니다.
- **문장별 글자 수 예산**: 한국어는 원문 길이의 0.7배, 영어는 1.6배입니다. Moonlight가 실제로 레이아웃에 맞춘 번역문의 길이 비율(중앙값 0.61, 90% 구간 0.74)에서 정했습니다. 예산은 요청에 `Character limits: 0:70, 1:85, …`로 함께 보냅니다.
- **사후 검사**: 예산의 1.25배를 넘은 문장은 압축을 한 번 다시 요청합니다. 예산의 0.35배보다 짧으면 내용이 빠진 것으로 보고 원문으로 되돌립니다(예: 저자 블록이 이름만 남은 경우). LaTeX는 렌더된 길이로 셉니다.
- **출력 형식**은 `<|i|>번역` 마커입니다(Moonlight 서버 응답 형식). 다음 마커가 도착하는 즉시 앞 문장을 확정하고, 빠진 문장은 원문으로 둡니다.
- **그 밖의 규칙**: 수식은 `$LaTeX$`로 씁니다. 인용, 그림·표·절 번호, 고유명사, 저자와 학회 줄은 그대로 둡니다. 한국어 번역 예시 한 쌍을 함께 보냅니다.
- **원문 유지**: 이메일이나 URL이 든 짧은 문장(저자·소속 블록)은 모델에 보내지 않습니다.
- **재시도**: 429는 `retry-after`를 따르고, 없으면 지수 백오프로 최대 5회 재시도합니다.
- **로컬 모델**: 한 쪽을 12문장 단위로 나눠 보내 앞부분이 먼저 나오게 하고, 요청은 한 번에 하나씩 처리합니다.
- **캐시**: 문장 단위로 한 줄씩 덧붙여 저장합니다. 모델이 빠뜨린 문장은 캐시하지 않습니다.

## 읽기 기능

- **진행도**: 레이아웃 유지 번역을 켜면 문서 전체를 백그라운드에서 번역하고, 상단에 “번역 중 n/전체쪽”과 진행 막대를 보여 줍니다. 지금 보는 쪽부터 뒤로 처리하고, 앞쪽은 마지막에 처리합니다.
- **확대·축소**: −/+ 버튼, 배율 메뉴, 트랙패드 핀치(포인터 위치 기준, Chromium의 ctrl+휠과 WebKit의 제스처 이벤트 모두 처리), ⌘+ / ⌘− / ⌘0을 지원합니다. 나란히 보기에서 핀치는 포인터 아래 화면만 확대하고, 버튼·메뉴·단축키는 두 화면을 같은 배율로 맞춥니다. 스크롤은 쪽 안의 위치 비율로 맞추므로 배율이 달라도 따라갑니다.
- **스크롤 동기화**: 휠 입력은 두 화면을 같은 프레임에 함께 움직입니다. 스크롤바 드래그와 키보드는 스크롤 이벤트로 맞춥니다.
- **확인 창**: Tauri 웹뷰에서 `window.confirm()`은 창을 띄우지 않고 `false`를 돌려주므로, 삭제와 비우기 확인은 앱이 직접 그립니다.
- **레이아웃 감지 입력**: 화면 캔버스 대신 긴 변 2048px로 따로 렌더한 쪽 이미지를 보냅니다. 확대 배율과 상관없이 같은 결과가 나오고, 확대 중 캔버스가 비워져도 감지가 실패하지 않습니다.
- **설정 창**은 일반(라이트·다크·시스템, 보기 편한 모드, 번역 언어), 번역 엔진, API 키 탭으로 나뉩니다. 다크 모드와 보기 편한 모드는 PDF 캔버스와 번역 블록에 같은 필터를 적용해 덮개 색이 어긋나지 않게 합니다.
